## 2. 怎么计费

```text
单次费用 = (未缓存输入token × 输入单价 + 计费输出token × 输出单价) / 1,000,000
整轮费用 = 所有规划、执行、恢复、工具往返请求费用之和
实验费用 = 每次episode运行费用累加，包含不同方法、种子、消融和重跑
```

输入包含提示词、语言指令、历史、工具返回和图像/视频编码 token；重复传入历史会重复形成输入。思考 token 计入输出，不能只按最终 JSON 的长度估算。[千问计费规则](https://platform.qianwenai.com/docs/developer-guides/getting-started/pricing)、[视觉 token 说明](https://platform.qianwenai.com/docs/developer-guides/multimodal/vision)

Qwen3.5 图像编码的官方估算采用缩放后高宽乘积除以32×32，再加2。例如缩放后640×480约302视觉token；全景、多图、历史图像及其他提示内容会叠加。实际收费以 API usage 为准，不能把这张图的例子当作一次完整导航请求。[视觉 token 说明](https://platform.qianwenai.com/docs/developer-guides/multimodal/vision)

## 3. Plus 规划 + Flash 执行的情景预算

以下均为自设工作量假设，不是测得的项目用量。输入数字已含文本和视觉 token；输出数字必须包含实际计费思考。所有单次请求均处于≤128K档，不计缓存、免费额度、额外工具或重跑。

| 情景 | Plus：调用次数×每次输入/输出 | Flash：调用次数×每次输入/输出 | 每轮episode | 100轮 | 1,000轮 | 5,000轮 |
|---|---|---|---:|---:|---:|---:|
| 精简上下文 | 5×5,000/500 | 30×2,000/150 | ¥0.053 | ¥5.30 | ¥53 | ¥265 |
| 中等工作量 | 10×10,000/1,000 | 100×5,000/300 | ¥0.288 | ¥28.80 | ¥288 | ¥1,440 |
| 多调用/长上下文 | 20×30,000/2,000 | 200×15,000/1,000 | ¥1.672 | ¥167.20 | ¥1,672 | ¥8,360 |

中等工作量算例：

```text
Plus  = 10 × (10,000×0.8 + 1,000×4.8) / 1,000,000 = ¥0.128
Flash = 100 × (5,000×0.2 + 300×2) / 1,000,000     = ¥0.160
合计 = ¥0.288 / episode运行
```

例如4组方法×1,000个episode×3次重复=12,000轮，按中等假设为¥3,456；若另留30%–50%的重跑/调试预算，约¥4,493–¥5,184。这是规模示例，并非已确定实验规模；是否需要随机重复及次数需按模型随机性和评测协议决定。

## 4. 与论文成本的区别

SpaceVLN 表7报告 Plus/Flash 在其缓存与调用配置下约$0.010/episode；其评测协议、prompt、缓存、模型时点及计费环境都可能与我们的不同。[论文附录C.3](https://arxiv.org/html/2606.08992v1)

该数字可以用作作者结果参考，不能直接承诺我们的每轮费用。我们的预算优先用实际 API usage 回算，保留模型ID、地域、输入token、输出/思考token、缓存读写、请求次数及恢复重跑记录。

## 5. 项目建议

- 首批接入先跑10–20个episode，设置小额试运行预算（建议¥100以内）；测出平均与P90单轮成本，再扩大评测。该建议不是充值或付费授权。
- 若采用 Plus/Flash 双模型，先限制每次上下文和输出/思考长度，减少重复发送图像与历史；记录这些限制对成功率和路径的影响。
- 分别报告 NoSignal、Reactive、StaticMap、Online Belief 的成本；规划不同会产生不同轨迹与调用次数，不能默认四组收费完全一样。
- 缓存用于完全相同的请求/前缀；发生轨迹分叉后不能用另一方法的回复替代真实决策。
- 托管 API 节省本地模型显存，仿真、视觉感知与信号场计算费用仍需单列。
