# B2开发pilot执行协议v0

制定日期：2026-11-09，首次B2导航结果出现前冻结。只用于工程开发，不能用于论文泛化结论。

1. 来源：保留R2R-CE train不变。取scene_id字典序前两个场景，每场景按episode ID数值升序选择五条不同trajectory_id的首个指令episode；共10个episode。导航失败不替换。源文件、navmesh、场景及模型/导航配置均登记hash。
2. AP：每场景用固定seed采样512个navmesh点。对各起点保留高度差≤0.25米且测地可达的点；取最接近6米、12米水平半径者，加起点AP，共三个布局。登记实际AP位置和半径；不以模型结果、outage或Oracle收益筛选AP。AP仅供仿真和评测。
3. 信号：沿用路线A代理，B2覆盖预算固定为1米RSSI=-48dBm、路径损耗指数2.8；其余参数沿用基线配置，弱信号/outage阈值=-67/-75dBm。该值是开发模拟假设，没有声称经过实测校准。B1参数与历史记录保持独立。
4. 执行：导航观察、模型revision/精度、工具接口和动作预算保持B1设定。每episode串行执行一次NoSignal，其完全不读RSSI，随后对相同轨迹做三个布局的信号回放。每个任务最多1800秒墙钟；中断、超时、解析失败、无进展和步数上限均记录为原样结果，不重采样。
5. 几何信息：低层执行器使用已知完整navmesh，只查询模型局部目标；禁止把任务goal或参考路径传给模型/控制器。这是已知几何下的开发设定，不代表未知地图导航能力。后续各对照保持同等几何访问。
6. 时间：0.25米前进=1秒，15度转向=0.5秒；RSSI在每动作末端采样，以该末端状态近似整个动作的暴露。模型推理等待时间另记墙钟，不计入当前运动暴露；没有模拟推理请求失联。
7. 汇总：SR/SPL以10个独立语言任务为分母；30个AP派生case不算30个独立导航样本。通信指标保留全部失败任务，同时可按成功/失败单独列出。单独统计缺失/部分轨迹，不能作为完整运行。
8. 验收：manifest和30个case完整、至少两个场景、失败原因可追溯、任意可导航位置可以查询信号。是否存在弱信号只说明benchmark具备暴露，不能证明绕路有益；B3仍须真正运行同一加权规划器的λ=0和StaticMap，报告导航、outage及绕行代价。

配置入口：`configs/benchmark/pilot_v0.json`。服务器清单：`data/derived/r2r_conn/pilot_v0/manifest.json`，拒绝覆盖已冻结版本。批量运行和回放入口分别为`scripts/run_pilot.py`、`scripts/replay_pilot.py`。
