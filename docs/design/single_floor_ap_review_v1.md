## 范围和筛选（先规则，后执行）

配置`configs/benchmark/single_floor_ap_review_v1.json`。仅源train，目标5个场景×每场景4条不同trajectory/source path=20条任务；按scene与episode数字排序选择满足技术规则的首批，不读任何模型成败或无线效果。5场景是本轮开发审阅规模，不是正式泛化评估。

1. 对全部train任务读取指令、start/goals/reference_path与dense GT层高；任一点缺失/非法记录原因。明确要求上下楼/乘电梯的任务标记excluded；仅高度变化超出0.20m、模糊提到楼梯/平台/台阶或有否定式楼梯措辞的任务标记review，不自动当合格或断言跨层。其余任务先进入几何检查。该文字/高度规则不是语义真值。
2. 所选候选的原reference_path逐段查询原生navmesh路径，确认可达且整个段不越出起点高度±.20m，再以≤.25m间距记录布局QA路线。该显示折线沿已验证的native path采样；不再让较粗的try_step网格重复否决其相邻点。几何路径高度超界转为review，不直接标作“上楼”；保持原指令/终点/参考锚点，不采用模型轨迹。
3. 场景按排序、原路径分组去重选4条；不足4条时记录场景原因后按既定排序继续。20条是开发审阅批次，不是规模充分性结论。未做原生几何检查的其余候选标记not_run，不称已通过正式资格。
4. 全部选中/排除/待复核/预算未选记录保存独立审计JSON，原始任务/楼梯任务和旧结果完全不动。不把新增20条替换原10条，不从旧B3删除97。

## AP与地图

单AP初始点由原路径35%进度附近的1.5m侧向目标吸附到原生navmesh验证的网格候选，候选距原路线≤2m。不按RSSI或Ours成功优化AP，不强制每条都存在弱区或可行绕行。AP使用floor proxy坐标，不声称真实墙/顶安装。

地图是原navmesh切片的可走节点/已验证边，不是带语义的建筑平面图。显示网格.40m，原路线采样点作为离线QA连接点补充窄门（非actor输入）。保存所有坐标、边、navmesh hash、路线与AP坐标。初始和编辑后的地图均显示粗网格 RSSI 估计。初始参考路线 RSSI 使用 route_a 原生 navmesh 距离代理；报告公开粗网格估计和原生参考路线的差异。

## 仅本机的HTML编辑

本机读取服务器产生的数据后生成一个无CDN/无外部请求的单文件HTML。可查看20任务/源路径/场景、原指令、全部源任务筛选统计/原因、路线、AP坐标、初始AP下原生latent truth与按采样序号加入确定性观测噪声的参考路线曲线，以及用同一truth公式和0.4m可走图Dijkstra距离计算的空间粗网格热图。v3 编辑 AP 时热图与草稿路线网格估计同步更新，保留初始 AP 原生路线曲线供对照。

地图点击吸附到合法可达候选，不接受任意墙内坐标；navmesh点阵/热图不是建筑平面图。热图是当前AP下的图距离粗估，不是原生逐点`SignalField.query`；路线truth曲线用原生navmesh代理，噪声曲线是同一接口的确定性观测样例，不代表闭环机器人轨迹。改点后热图可辅助校正，但必须再运行原生场重算，不能冒充真实传播或物理测量。空间长度暴露不等于运动/推理断连时长。

支持浏览器本地草稿、重置及导出/导入修改JSON，包含源/几何hash、初始/修改点和待复核标记。HTML和修改记录只保存在本机`runtime/reports/`，不上传GitHub或服务器。编辑不会写回服务器正式配置；人工调整属于development layout design，应另立版本记录，后续原生重算/QA再冻结，不作为旧批次结果。

尚未完成的语义视觉标注/许可对应与物理无线保真限制仍保留；本轮是布局审阅工具与新开发样本，不是benchmark论文结果或发布验收。
