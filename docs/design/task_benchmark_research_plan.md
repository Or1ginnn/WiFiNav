## 3. 调研产物与决策依据

1. **任务比较表：** 输入、可用观测、目标定义、动作与停止条件、成功/路径指标、未知地图设定、数据许可、服务器已有资产和新增工作量。
2. **近期方法与代码表：** 重点核查2025–2026工作；记录是否有完整官方代码/权重、模型调用方式、既有导航训练、Habitat版本、子目标/路径接口。缺实现不写作可复现。
3. **通信决策价值检查：** 任务中是否真实存在通信质量不同且导航代价可接受的路线？是否出现“目标必在盲区”“指令唯一指定路线”等退化情形？将其作为分层场景，不能通过挑样本隐藏。
4. **最小改造方案：** 分别给出VLN与ObjectNav的一页方案和工作量；按研究价值、复现资源、可解释性与实施成本推荐主任务。
5. **任务决策记录：** 写入 `plan.md` 的T0，明确选择/排除原因及未解决假设，再冻结对应框架和episode清单。

## 4. benchmark 调整需要设计的内容

- **原任务保持可追溯：** 保留源scene/episode/指令或目标ID、原始划分与原指标；新增通信层不静默重写任务成功定义。若筛选episode，公开规则、覆盖率与未筛选参照。
- **无线条件：** AP布局/数量、覆盖强度、墙损、噪声、时间变化、随机种子和采样周期。完整场仅供模拟器/Oracle；在线方法只读取截至当前时刻的允许观测。
- **泛化划分：** 分开控制scene、episode、AP布局与传播参数；开发集用于调λ/阈值，保留评估集不参与选择。共享底图时明确AP布局的独立性。
- **任务语义：** VLN的路线/顺序约束与ObjectNav的目标探索不能混为同一个成功判定；是否允许通信绕行、预算如何计算需在任务定义中说明。
- **时间与服务：** 路径长度、仿真运动时间、实际模型延迟分别记录。只有明确定义真实/模拟链路和超时策略，才将网络变化映射为推理失败；网络正常的本地服务不能充当真实断网证据。
- **对照与公平性：** NoSignal、当前信号Reactive、在线估计和StaticMap使用同一导航/模型/执行预算；同一加权规划器λ=0对照；若用不同模型，单独分组，不混归因。
- **指标：** 原任务成功与路径效率 + outage总时长/比例、最长断连、绕行、耗时与请求失败；用联合曲线表达权衡，避免仅以一项通信指标宣称更好。
- **可复现包：** 数据生成脚本、配置/布局清单、坐标变换、任务映射、评测代码和版本；场景网格遵循原许可，不默认可以再分发。
