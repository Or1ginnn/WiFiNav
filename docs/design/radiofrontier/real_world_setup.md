# RadioFrontier 现实场景描述与设置
==RadioFrontier（我们的方法）
Frontier（原始方法）==

## 一、现实场景目标

本场景用于展示并验证 RadioFrontier 在真实办公室或实验室中的通信感知 Object Navigation 能力。

机器人接收任务：

> 在当前室内环境中寻找一个蓝色杯子。

机器人从固定起点出发，初始时不知道：

- 蓝色杯子的具体位置；
- 协作式无线锚点的真实位置；
- 尚未探索区域的完整几何；
- 尚未经过路径上的通信质量。

机器人通过 RGB-D、Pose 和已探索区域建立局部占据地图，使用 OpenFrontier 生成 visual frontiers。RadioFrontier 仅在语义合理的候选 frontier 中，根据历史 CSI 和候选路径预测未来通信中断风险，并在固定额外路径预算内完成重排序。

现实场景需要表达的核心结论是：

> RadioFrontier 不是让机器人追着 WiFi 信号移动，而是在仍然优先完成目标搜索的前提下，以有限的额外路径代价减少长时间通信中断。

---

## 二、场景总体布局

现实场地采用“共同预热轨迹 + 中央方形柱子 + 左右双 visual frontier + 柱后目标”的结构。以下为俯视图：

```text
                  ┌────────目标桌面────────┐
                  │    蓝色杯子（偏左）     │
                  └────────┬──────────────┘
                           │
           路线 A          │           路线 B
         较短/NLOS         │         略长/较稳定
              │       ┌────┴────┐       │
              │       │         │       │
   Frontier A ●       │ 方形柱子 │       ● Frontier B
              │       │         │       │
              │       └─────────┘       │
              └─────────┐   ┌───────────┘
                        │决策点│
                        └──┬───┘
                           │
                     共同预热轨迹
                  约 3-5 m，至少一次转弯
                           │
                      固定起点 Robot

          协作式无线锚点位于柱子右侧、靠近路线 B
```

方形柱子遮挡机器人对柱后区域和蓝色杯子的视线。机器人到达柱子正面时，柱子左右边缘分别形成 Frontier A 和 Frontier B；两者是两个不同的高层探索候选。蓝色杯子放在柱后偏左位置，使路线 A 略短；无线锚点放在柱子右侧，使路线 B 通信更稳定但距离略长。

---

## 三、场地选择要求

场地优先选择具有以下结构的办公室、实验室或教学楼区域：

- 起点与柱子之间存在一段共同接近轨迹；
- 中间有一个足以遮挡相机视线的方形柱子；
- 柱子左右两侧均有足够机器人安全通过的空间；
- 柱子左右边缘能形成可被 OpenFrontier 检测的两个 visual frontier；
- 两侧路径在柱后重新进入同一目标区域；
- 蓝色杯子位于柱后且从起点和决策点不可见；
- 路线 A 因目标偏左而稍短，但与锚点之间更多被柱体遮挡；
- 路线 B 更靠近无线锚点，LOS 比例更高；
- 两条路线均满足机器人安全导航要求；
- 柱体材料和尺寸能够产生可重复测量的无线差异。

不采用以下场地：

- 柱子一侧无法安全通行；
- 两个候选方向的语义差异过大；
- 绕柱两侧路径无法在柱后到达同一目标区域；
- 路线 A 从起点开始就完全失联；
- 两条路线均处于满格强信号；
- 低层导航器无法稳定通过的狭窄或动态区域。

---

## 四、共同预热轨迹

共同预热轨迹位于机器人起点与柱前决策点之间，建议长度约 3-5 m，并至少包含一次转弯。

该轨迹用于：

- 让 Original OpenFrontier 和 RadioFrontier 具有完全相同的初始轨迹；
- 采集第一段双向 CSI 历史；
- 初始化 Bearing 和 AP belief；
- 验证 CSI frame pairing、实际采样率和 Pose 时间对齐；
- 避免 RadioFrontier 在第一次关键决策时没有足够无线观测。

共同预热轨迹不能提前经过路线 A 或路线 B 的主要测试区域，也不能向算法泄露未来路径信号。

到达柱前决策点时，如果满足以下任一条件，RadioFrontier 必须回退到 Original OpenFrontier：

- 有效 CSI 配对样本不足；
- Bearing 置信度低于阈值；
- AP belief 仍接近均匀分布；
- 路径预测不确定性超过阈值；
- CSI 或 Pose 时间同步异常。

## 五、双 Frontier 设置

### 5.1 Frontier A：较短但通信风险较高

Frontier A 对应的路径具有以下特征：

- 路径长度较短；
- 与目标语义相关性合理；
- 从方形柱子左侧绕行；
- 蓝色杯子位于柱后偏左，因此到达目标的几何距离较短；
- 柱体遮挡机器人与右侧无线锚点之间的直达路径；
- 绕柱左侧阶段具有较长弱信号区；
- 弱信号区能够在多轮 Radio Survey 中重复出现；
- 可能导致视频帧丢失、请求超时或 stale decision；
- 不影响机器人本地安全控制和紧急停止。

### 5.2 Frontier B：略长但通信更稳定

Frontier B 对应的路径具有以下特征：

- 路径比 A 略长；
- 与目标语义相关性同样合理；
- 从方形柱子右侧绕行；
- 因杯子位于柱后偏左，路线 B 需要多走一小段；
- 路径更靠近柱子右侧的无线锚点；
- 与无线锚点之间具有较少遮挡路段；
- 通信质量整体更稳定；
- 最长连续中断明显短于路线 A；
- 额外路径长度不超过预先冻结的预算。

建议将路线 B 相对路线 A 的长度增加控制在约 10%-25%，但正式阈值应根据场地测量和机器人导航误差预先冻结。

### 5.3 候选公平性

Original OpenFrontier 和 RadioFrontier 必须共享：

- 相同 RGB-D 与 Pose 输入；
- 相同 visual frontier 检测结果；
- 相同 Top-K 语义候选；
- 相同 frontier 原始语义效用；
- 相同候选路径生成器；
- 相同低层导航器；
- 相同停止条件；
- 相同最大额外路径预算。

RadioFrontier 只能额外使用历史 CSI、AP belief、候选路径几何和预测不确定性。

## 六、目标物体设置

目标物体为一个蓝色杯子，放置在方形柱子后方的桌面、柜面或台面上，并相对柱子中心略偏向路线 A 一侧，使路线 A 在几何上稍短。

杯子应满足：

- 蓝色明显且颜色稳定；
- 尺寸适中；
- 位于 RGB 相机可见高度；
- 被方形柱子完整遮挡，从起点和柱前决策点均不可见；
- 机器人从柱子任意一侧绕到柱后后均能观察到；
- 不透明、不过度反光；
- 周围留有机器人可到达的成功区域。

场景中可以放置以下干扰物：

- 白色或红色杯子；
- 蓝色水瓶；
- 蓝色文件夹；
- 其他蓝色非杯类物体。

任务成功同时满足：

```text
检测类别为 cup
+
颜色属性为 blue
+
机器人到达规定成功距离
+
机器人执行停止动作
```

## 七、协作式无线锚点设置

现实场景使用一个固定、协作式无线锚点。这里不假设任意商用 AP 都能提供双向复数 CSI。

需要固定并记录：

- 锚点位置与高度；
- 天线方向与安装方式；
- WiFi 频段与信道；
- 发射功率；
- 数据包发送频率；
- 正向/反向请求-应答协议；
- frame number 生成与配对规则；
- 实际 CSI 采样率；
- 锚点与机器人时钟关系。

锚点真实坐标只能用于：

- Oracle baseline；
- AP belief 定位误差；
- Radio Survey；
- 观众界面中的真值标记。

锚点真实坐标不能作为 RadioFrontier 在线输入。

---

## 八、机器人与 CSI 设备设置

机器人至少配备：

- RGB-D 相机；
- 机器人定位与里程计；
- 可导出复数 CSI 的无线设备；
- 独立的安全控制或管理链路；
- 本地低层导航与紧急停止；
- 时间同步与统一日志系统。

每个无线数据包至少记录：

```text
timestamp
frame_number
tx_node_id
rx_node_id
forward_complex_csi
backward_complex_csi
pair_valid_mask
rssi
snr
noise
packet_sequence
robot_pose
pose_timestamp
```

正式运行前必须确认：

- 静止和运动状态下均能采集双向 CSI；
- 正反向包可以通过 frame number 配对；
- CSI 与 Pose 时间轴可以对齐；
- 配对率、丢包率和实际采样率有日志；
- CSI 采集失败不会影响机器人安全控制；
- 断网时机器人可以本地停止或继续执行安全动作。

---

## 九、现实通信差异设置

路线 A/B 的通信差异优先通过真实空间结构产生：

```text
方形柱子的材料与尺寸
+ 无线锚点位于柱子右侧
+ 左侧绕行时的柱体遮挡
+ 右侧绕行时的较多 LOS
→ 形成空间通信差异
```

方形柱子优先选择钢筋混凝土、砖石或其他能够产生稳定衰减的实体结构。普通装饰性空心柱可能只产生视觉遮挡，未必能形成足够无线差异，必须通过 Radio Survey 验证。

若整个场地信号过强，可以统一调整：

- 锚点发射功率；
- 锚点天线方向；
- 锚点安装高度；
- 射频衰减器；
- 锚点与柱子的相对位置；
- 柱子附近固定金属柜或大型设备的位置。

不允许针对某一种方法单独改变无线条件。

---

## 十、应用层网络失败映射

真实 CSI、RSSI 和 SNR 负责描述无线状态。为了稳定复现视频卡顿和 VLM 请求失败，可以使用统一的确定性网络映射：

```text
高 SNR：正常带宽、低延迟、低丢包
中 SNR：中等带宽、增加延迟和少量丢包
低 SNR：带宽受限、高延迟、高丢包或请求超时
```

必须满足：

- 映射函数和阈值在正式对比前冻结；
- Original 和 RadioFrontier 使用完全相同的映射；
- 映射模块不能生成或修改 CSI；
- 原始真实链路指标与映射后的应用指标分别报告；
- 真实云端 API 仅用于 Demo，不作为唯一实验依据；
- 主实验可以使用固定 trace 回放保证可重复性。

## 十一、场地验收

正式实验前，人工推动机器人沿共同预热轨迹、路线 A 和路线 B 多次移动。

记录：

- 双向复数 CSI；
- CSI 配对率；
- RSSI 与 SNR；
- packet loss；
- RTT 与 goodput；
- 机器人位置和朝向；
- 门状态和环境时间戳。

路线 A 验收要求：

- 存在可重复的连续弱信号区域；
- 最长中断不是由单次异常包造成；
- 起点和预热走廊不完全断网；
- 机器人本地安全控制始终正常。

路线 B 验收要求：

- 整体通信比 A 稳定；
- 最长连续中断短于 A；
- 路径长度仍在预算内；
- 能够安全到达目标区域。

Radio Survey 只用于场地验收、参数冻结和 Oracle 标签，不能作为在线未来路径输入。

若需要真实数据校准，校准轨迹必须与最终测试轨迹和测试时段分离。

## 十二、现实运行流程

```text
系统初始化
→ 执行共同预热轨迹
→ 采集并配对双向 CSI
→ 更新 Bearing 和 AP belief
→ OpenFrontier 生成 Top-K visual frontiers
→ 为每个 frontier 生成候选路径
→ 预测路径 outage、P5 SNR 和不确定性
→ 应用语义约束与额外路径预算
→ 选择 frontier
→ 执行一小段路径
→ 滚动更新
→ 发现蓝色杯子并停止
```

如果两条候选路径通信风险相近，选择原始效用更高或更短的路径。

如果稳定路径超出最大额外路径预算，不允许为了通信质量选择它。

如果无线预测无效或不确定性过高，回退到 Original OpenFrontier。

---

## 十三、配对实验设置

现实对比采用多轮配对实验，而不是只运行 Original 和 RadioFrontier 各一次。

每对实验固定：

- 起点；
- 蓝色杯子位置；
- 锚点位置和发射功率；
- 门和遮挡状态；
- OpenFrontier 配置；
- 视觉模型；
- 低层导航器；
- 网络映射或 trace；
- 额外路径预算。

实验要求：

- 方法运行顺序随机化或交叉；
- 使用相同场景、episode 和 seed 配对；
- 每种方法重复多轮；
- 保存所有成功、失败和回退运行；
- 选择效果最好的视频；
- 报告配对差值、置信区间和失败案例。

## 十四、现场界面

现场界面建议包含四个区域。

### 14.1 机器人第一视角

- 当前 RGB 图像；
- 目标文本；
- 蓝色杯子检测结果；
- VLM 请求状态；
- Effective FPS。

### 14.2 导航地图（鸟瞰图）

- 已探索局部地图；
- visual frontiers；
- Top-K 候选；
- 候选路径；
- 当前选择；
- 机器人历史轨迹。

### 14.3 无线状态

- CSI 采样率与配对率；
- RSSI 与 SNR；
- packet loss 与 RTT；
- Bartlett AoA profile；
- Top-K Bearing peaks；
- AP belief heatmap；
- 锚点真值，仅观众可见。

### 14.4 路径风险与决策

- 每条路径长度；
- 预测 P5 SNR；
- outage probability；
- 最长预测弱信号段；
- 预测不确定性；
- 原始 frontier utility；
- 最终 frontier score；
- 是否触发回退。

## 十五、评价指标

主指标：

- ObjectNav Success Rate；
- SPL；
- 额外路径长度；
- Outage Ratio：整个导航中处于通信中断状态的时间比例；
- Stale Decision Ratio：因网络失败而继续使用过期导航决策的时间比例。

辅助指标：

- 完成时间：从任务开始到找到杯子并停止的总时间；
- Average/P5 SNR：整条轨迹的平均信噪比；；
- Packet Loss；
- RTT；
- Effective FPS；
- CSI pair success rate：正向和反向 CSI 成功配对的比例；
- Bearing confidence：表示系统对预测锚点方向的确定程度。；
- AP belief entropy：表示 AP 位置概率分布的不确定性；
- fallback rate：表示系统因为无线感知不可靠而回退到 Original OpenFrontier 的决策比例。

现场最需要突出：

```text
有限的额外路径长度
+
更短的最长连续中断
+
更少的 stale decision 或请求超时
```
