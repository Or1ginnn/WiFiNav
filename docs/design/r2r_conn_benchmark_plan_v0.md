# 连通性感知VLN与R2R-Conn制作计划 v0

日期：2026-11-04。状态：**以原proposal为起点的执行建议，具体协议尚未正式冻结；未生成数据或开展导航实验。**

## 1. 工作起点与任务建议

主线沿用原提案的连通性感知VLN。第一版建议采用 **MP3D + R2R-CE**，暂称R2R-Conn；RxR-CE在闭环稳定后扩展。任务是：机器人接收原始自然语言指令，在未知无线覆盖下沿途采样RSSI，一边遵循指令到达目标，一边降低弱信号暴露和断连风险。

选择MP3D作为首版底图的依据是官方VLN-CE数据与这些场景对齐；原提案中的“HM3D + R2R轨迹”不能直接照搬，迁移到HM3D需要另做任务与指令对齐。已有Habitat环境不等于已具备匹配任务、数据和导航执行代码。[VLN-CE官方数据说明](https://github.com/jacobkrantz/VLN-CE#data)、[R2R原始资源](https://github.com/peteanderson80/Matterport3DSimulator#room-to-room-r2r-navigation-task)

**当前的工作是核查并完成这一任务的具体协议和改造可行性。** ObjectNav保留为遇到实质问题时的回退方向，若需切换必须单独记录决策，不重新把全部任务并列泛选型。

## 2. 最重要的任务规则：到达不等于遵循指令

- v0保留原始指令、起终点、参考路径与任务成功判定；不把指令改写成只要求到达同一目标。
- 通信绕行会改变路线：SR/SPL评估到达与效率，nDTW/SDTW反映参考路径偏离。报告两侧的权衡，不能因断连减少就宣称整体更好。nDTW是路径相似性指标，不是对自然语言约束是否满足的完美判定。[nDTW原论文](https://arxiv.org/abs/1907.05446)
- 开发样例需人工核查指令中的必经地标、顺序及歧义，记录绕行冲突案例。此记录用于诊断；若新增结构化语义成功指标，必须另有明确标注和验证，不将VLM自评分当真值。
- 若后续设计“允许局部绕行但保持关键地标顺序”的新任务，单独发布版本、标注规则和新指标，与保留原指令的v0分别报告。
- 绕行空间很小、指令强指定路线、目标在弱覆盖区等情况都应如实呈现。它们可能说明任务无法同时改善两侧，而非算法必然失败或样例应被删除。

## 3. benchmark的组成

制作目标是可复现的**交互任务扩展、无线生成器与评测协议**。只给原参考轨迹补RSSI，无法评估机器人偏航后的信号，也不足以支持在线建场。

| 层 | 制作内容 | 质量要求 |
|---|---|---|
| 原始任务 | source版本、scene、episode、path/instruction ID、起始位姿、目标、参考路径、split | 原始内容可追溯，不静默改变成功定义 |
| 无线实例 | AP位置/高度/功率、传播参数、噪声seed、覆盖配置 | 真值封装在模拟器；同一实例可重复生成 |
| 可查询信号场 | 允许对任意实际机器人位置查询RSSI；必要时按楼层建场 | 覆盖可走区域，坐标和单位一致，不只存参考轨迹标签 |
| 在线接口 | 按执行时间在当前位姿采样RSSI；明确缺测/掉线行为 | 在线模块只见截至当前时刻的观测 |
| 评测与清单 | 原导航指标、通信/路径指标、联合曲线、任务/布局分层 | 失败和零断连样本保留；记录每项分母与预算 |

建议派生ID为 `source_episode + layout_id + channel_seed`，另保存共享原始路径的group ID。一个episode的多个AP布局不是独立的新语言任务。

## 4. 无线层：先可控，再保真

### 路线A：最小闭环

- 首轮先单AP，静态大尺度场 + 可复现阴影/测量噪声；参数显式写配置。单点随机噪声不代替具有空间相关性的覆盖场。
- AP在物理可行位置采样；位置/功率/布局对在线agent隐藏。信号生成器可使用场景几何，但墙体/完整场不因此自动成为agent输入。
- 用3D距离处理高度；跨楼层场景须单独验证。pilot如只支持单层，发布过滤规则与排除数量，不宣称覆盖完整R2R-CE。
- RSSI阈值、采样周期、相关长度、墙损与时间推进在开发集上做物理合理性检查后固定。阈值是场景/设备假设，不写成普遍物理常数。
- 每个场景保留覆盖较好、局部弱区、严重覆盖不足等预定义条件。区分随机布局集合与专门构造的双路径诊断集合，不用Ours的成功表现选AP或删实例。

### 路线C：独立验证

小样例通过后，用Sionna RT离线覆盖图 + 在线位置查询替换一部分信号源，并考虑真实RSSI回放/采集。几何转换、射频材质和坐标对齐先做小场景。独立信号源用于检验模型失配，不能仅在同一公式生成/估计的场上宣称泛化。

### 信息与地图边界

- 模拟器/评测器可使用完整场、AP配置和真实几何；它们不作为在线方法输入。
- agent的RGB-D、位姿、局部地图权限对所有方法相同。先明确是否采用理想位姿；不能一边用全场navmesh选路，一边声称未知几何地图。
- 官方示例含训练/评估用oracle传感器。接入时需剔除或隔离 `SHORTEST_PATH_SENSOR`、`VLN_ORACLE_PROGRESS_SENSOR` 等，不将参考路径/真值进度送入Qwen或belief。[官方任务配置](https://github.com/jacobkrantz/VLN-CE/blob/master/habitat_extensions/config/vlnce_task.yaml)
- StaticMap只增加无线真值信息，尽量保持几何观测和执行器相同；完整几何全局规划只作额外诊断，不与在线方法混为同一对照。

## 5. 指标、时间与公平性

1. **导航：** 按锁定的源协议报告SR、SPL、nDTW，可补SDTW和NE。成功距离/停止规则直接核对配置；不只看是否靠近终点。
2. **通信：** outage总时长、outage比例、最长连续outage、弱信号暴露；补充空间采样长度占比，防止算法通过快走或提前失败获得表面收益。
3. **代价：** 路径长度、动作步数、模型请求数、实际推理延迟和任务完成率。失败样例不能从通信指标分母中静默排除，成功条件结果与全样本结果分开报告。
4. **时间定义：** 明确移动/转向的仿真时长，区分运动时间、模型等待时间和墙钟时间。初版可先报告运动时间下的无线暴露；加入“等待推理时也会断网”的结论时，必须显式模拟/测量等待阶段。
5. **主要图：** SR/SPL/nDTW—outage、路径增加—outage的λ曲线。基线outage为0时报告绝对差，不计算无意义的相对改善。
6. **统一预算：** 同一Qwen版本/精度/观察/历史预算、动作与停止规则；局部目标执行消耗的底层动作也计入步数。替换旗舰模型时主要对照同步更换。
7. **λ=0：** 保持同一加权规划器作NoSignal消融，避免把换规划器的收益归因给信号。原导航框架结果可另外保留。

官方R2R-CE示例使用0.25m前进、15度转向、500步上限、3m成功距离；具体采用哪组观察/动作设置须随选定实现锁定。RxR Challenge配置不同，不能直接混用或把全景输入结果称作满足其官方协议。[R2R任务配置](https://github.com/jacobkrantz/VLN-CE/blob/master/habitat_extensions/config/vlnce_task.yaml)、[RxR配置说明](https://github.com/jacobkrantz/VLN-CE#rxr-habitat-challenge)

初版先在网络正常条件下使用现有模型服务，独立评价信号场与路线。RSSI与实际吞吐/超时没有一一对应关系；推理请求失败实验需另给链路模型/测量、请求时序和回退策略。

## 6. 制作阶段与验收

| 阶段 | 建议规模与工作 | 验收产物 / 进入下一阶段的条件 |
|---|---|---|
| B0 资产与协议核对 | 盘点已有MP3D/R2R-CE、许可、scene/episode/GT版本；确认导航执行实现、Habitat适配和模型/仿真显存共存 | 版本与资产清单、一页任务协议；当前模型部署不等于此项完成 |
| B1 单条贯通 | 1个scene、1个episode、1个AP布局 | RGB-D/位姿/导航动作/RSSI对齐；任意偏航位置可查信号；一份完整日志和轨迹图 |
| B2 开发pilot | **10个原始指令episode，至少2个scene × 每episode 3个布局 = 30个派生case**；独立双路径几何诊断另列 | 固定manifest、生成脚本/配置、字段与单位说明；全部失败/不可绕行情况保留；不用于显著性或泛化结论 |
| B3 Oracle验收 | 先同一导航栈NoSignal vs StaticMap及有限λ扫描 | 导航—通信权衡图；若无收益，诊断路线空间/信号对比/规划接口/指令冲突，不直接扩大数据或加训练 |
| B4 小规模评估 | 建议**100个原始episode、目标覆盖至少10个scene、每episode 3个布局**，视可用资源修订 | 无调参泄漏的保留评估集；加入Reactive与Online Belief，报告不确定性与失败分析 |
| B5 扩展与发布 | B3/B4通过后再扩大任务量、多AP、噪声/传播失配、部分Sionna、可选RxR | 生成器、任务/布局清单、评测代码、版本/协议卡、结果与许可说明 |

上述数量是制作建议，不是现有数据或统计充分性保证。30个case×4种方法意味着最多120次rollout，λ/随机种子还会增加运行量；先测一条完整episode的耗时再预算。首轮不为了覆盖所有方法等待belief实现，先完成NoSignal与Oracle。

若无线只影响离线指标、NoSignal完全不读无线且执行不受链路影响，其固定seed轨迹可跨AP布局做信号回放，减少重复推理；其他依赖信号或服务中断的策略不能用这种方式替代真实闭环。

## 7. 数据划分与实例审计

- 保留源数据split；开发从训练场景抽取，不为新增任务训练模型权重。保留评估使用原val_unseen中未参与开发的场景/任务，明确这是我们扩展上的评估，不冒称官方隐藏test成绩。
- 同一源路径的多指令、多布局、信道seed按组管理，不能跨开发/评估泄漏。AP与传播参数族也独立登记；重复布局不作为独立语言任务放大样本量。
- 冻结样本和λ/阈值选择规则后再评估；报告按scene或源路径分组的不确定性，不把全部AP派生case视作独立样本。
- 按覆盖水平、初始连通状态、路线长度、可绕行程度和楼层情况分层报告。预设几何/物理可用性过滤条件，发布排除清单和原因；不能根据某个模型是否成功筛选评估样本。
- 不预先规定每个方法必须有正收益。Oracle未改善时检查候选路径/目标约束/指标，允许得出该子任务通信优化空间不足的结论。

## 8. 文件与发布约定

Git内建议逐步增加：`configs/benchmark/`、`scripts/generate_benchmark.py`、`src/connectivity_vln/{signal_simulation,evaluation}/`及小型manifest样例。它们目前尚未实现，不预造生成器或结果。

服务器大数据放checkout外的独立dataset目录，实际位置在B0登记；已有模型在WiFiNav_runtime/models，旧备份保持不动。每个case至少记录：源版本与hash、scene/episode/path/instruction ID、split、start/goal引用、坐标/楼层、AP布局/信道seed、信号生成版本、阈值/时间定义、覆盖分层和过滤原因。

先发布代码、可再分发的生成参数与评测协议；原场景、任务文本和派生数据的再分发遵循源许可，不能把开放代码许可当作场景再分发许可。[VLN-CE许可说明](https://github.com/jacobkrantz/VLN-CE#license)
